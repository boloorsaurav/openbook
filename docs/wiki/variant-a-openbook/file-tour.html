If you only learn ten files

File Tour

The codebase has hundreds of files but ten of them carry most of the meaning. Read these and you can navigate the rest by analogy.

1. src/app/layout.tsx — the global wrapper

Every page in a Next.js App Router app is wrapped by this one file. It sets up the <html> and <body> tags, loads the two fonts (Outfit and Inter via next/font/google), and applies them as CSS variables. After that, individual page files just render their content — they never have to think about fonts or HTML boilerplate.

2. src/app/page.tsx — the homepage

The landing page at /. Lists the three course tracks (NCERT Math, Engineering Math, Advanced Math) and the available grades within each. The Grade 11 entry links to /read/grade-11/ch1; future grades show "coming soon". Pure presentation — no state, no data fetching.

3. src/app/read/grade-11/ch1/page.tsx — a typical chapter

The shape every chapter follows. Reading this one file gives you the mental template for all 14 Grade 11 chapter pages. The structure, in order:

  1. "use client"; directive — tells Next.js this page uses interactive widgets.
  2. Imports — layout pieces, widgets, the quiz pool.
  3. CHAPTERS array — the sidebar entries (one entry per chapter in the grade).
  4. export default function ChapterPage() — returns JSX.
  5. Inside: a Navbar, a sticky Sidebar, then a <main> with numbered sections, callouts, widgets, the quiz, and a footer.

4. src/components/layout/WidgetShell.tsx — the universal wrapper

A 45-line component. Renders a rounded card with a header bar and a body. Takes three props: a label string for the header, an optional badge, and children. Every widget wraps itself in this so the visual treatment of widgets is consistent across the whole site without any per-widget effort.

5. src/components/widgets/Quiz.tsx — used by every chapter

The one widget that appears in every single chapter page. Takes a pool of typed QuizQuestion objects and a count (default 10). Samples randomly, shows progress, supports hint-on-demand, marks correct/wrong, displays an explanation, and ends with a score screen. The pool itself lives in src/data/<slug>-questions.ts.

6. src/app/globals.css — the design tokens

The single source of truth for colour, font, shadow, and border variables. Both Tailwind utilities and inline style attributes read from these tokens. To change the palette or font of the entire site, you edit this one file. See the Design System page for the breakdown.

7. src/data/grade-11-ch1-questions.ts — a typical quiz pool

All quiz pools follow this exact shape. The file exports a typed array (GRADE_11_CH1_QUESTIONS: QuizQuestion[]) with 20–30 question objects. The Quiz widget samples 10 at random per attempt. 

export const GRADE_11_CH1_QUESTIONS: QuizQuestion[] = [
  {
    question: "Which of the following is a set?",
    options: ["Tall people", "Vowels in English", "Good books", "Funny jokes"],
    answer: 1,
    hint: "A set must be well-defined.",
    explanation: "'Vowels in English' is unambiguous; the others are subjective."
  },
  // ...
];

8. src/data/briefs/grade-11-ch1-brief.md — a typical brief

The intermediate artefact from Stage 1 of the pipeline. Plain Markdown, structured to a strict schema. Read once by Claude during chapter authoring, then committed to the repo so the next maintainer (or a future audit) can see what the chapter was built from. Never read at runtime by the website itself.

9. .claude/skills/create-chapter/SKILL.md — the workflow doc

Defines the create-chapter skill that Claude reads when you say "build chapter N for class M". Contains the full Stage 1 + Stage 2 workflow, a quality checklist, and what NOT to do (don't read the raw PDF, don't push to main directly, don't ship without the quiz). See the Chapter Pipeline page for the human-readable version.

10. .claude/skills/create-chapter/scripts/make-brief.sh — Stage 1 script

A bash script. Takes a PDF path and a slug, runs pdftotext, sends the result to DeepSeek with the strict prompt, saves the response to src/data/briefs/<slug>-brief.md. About 110 lines total, mostly preflight checks and helpful error messages. The actual API call is one curl command.

Honourable mentions

  • src/components/layout/Sidebar.tsx — the left rail. Reads a CHAPTERS array and renders a list with the active item highlighted.
  • src/components/layout/CalloutCard.tsx — the soft-coloured box used inside prose. Two props: title and children.
  • src/components/layout/Navbar.tsx — the top bar. Used by every page. title prop is optional (homepage doesn't set one).
  • CLAUDE.md at the repo root — project-level instructions Claude reads at the start of every session. Names the design tokens, the page template, the widget pattern. The shortest-path doc for getting a new contributor productive.
  • AGENTS.md — a one-liner reminding Claude that Next.js 16 has breaking changes vs older versions, so always read the relevant doc in node_modules/next/dist/docs/ before writing Next.js code.
Deep diveHow CLAUDE.md and AGENTS.md interact

CLAUDE.md is project-specific guidance — the design tokens, the page template, the rule that says "every widget wraps itself in WidgetShell". AGENTS.md is a hint that Next.js 16 isn't the Next.js 13 Claude was trained on. Claude reads both at the start of every session, and the create-chapter skill augments them with workflow-specific instructions for chapter building.

The same pattern works for any Claude-managed project: keep project context in CLAUDE.md, framework hints in AGENTS.md, and named workflows in .claude/skills/<name>/SKILL.md.
