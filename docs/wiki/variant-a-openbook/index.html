Welcome

Openbook, end to end

Openbook is a static Next.js site that turns NCERT chapters into interactive learning pages. This wiki is the manual to its codebase — written so a smart PM can read top-to-bottom and an engineer can dive into any section.

The 30-second version

Each chapter is one TypeScript file (page.tsx) that imports a few shared layout pieces (Navbar, Sidebar, CalloutCard), drops in widgets where helpful, and ends with a quiz. The site is fully static — no backend, no database, no accounts. New chapters are built by handing a PDF to a 2-stage pipeline: DeepSeek extracts a clean brief from the PDF (cheap), then Claude turns the brief into a chapter page (token-efficient).

Tech stack at a glance

Next.js 16The framework. We use the App Router with static export — pages are pre-rendered to plain HTML at build time.
React 19The component model. Every chapter page and every widget is a React component.

Tailwind CSS v4Utility-first styling. We mostly use the tokens defined in globals.css rather than raw utility classes.
Framer MotionAnimation library — used sparingly in some widgets for smooth transitions.
KaTeXMath typesetting (installed but rarely used — most formulas are plain Unicode or inline mono text).
VercelHosts the live site. Auto-deploys on push to main; PRs get preview URLs.
DeepSeek APIUsed by the chapter-building skill to extract a brief from a PDF cheaply (~$0.02 per chapter).

Deep diveWhy static export?

Next.js can run as a long-lived server or it can pre-render every page at build time into plain HTML files. Openbook uses the second mode (called "static export"). The site has no server-side logic, no per-request work, no database — every visitor gets the same pre-baked HTML. That makes hosting trivial (any static file host works), makes it extremely fast, and removes a whole class of bugs and security concerns. The trade-off is that anything personalised would need to happen in the browser (none does, today).
